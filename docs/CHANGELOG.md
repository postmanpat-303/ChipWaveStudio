### Automation UX stages 3–8 (design A)
- **Stage 3:** song lanes **migrate** onto track lanes when entering timeline mode; a **Song / Master** track holds tempo, master volume and returns; Tempo can be a track lane; old songs stay bit-exact.
- **Stage 4:** per-track **Read / Touch / Latch / Write / Off** write modes; global **Write** toggle in the Automation strip.
- **Stage 5:** timeline tools **Pointer / Pencil / Line / Shape** (shape stamp); bigger hit targets from stage 1.
- **Stage 6:** clip envelopes **Absolute / Relative + / Relative ×**; Glue **keeps and merges** clip automation; relative lanes draw blue/dashed.
- **Stage 7:** **38xx–3Bxx** command diamonds on cutoff/resonance lanes; **modulation band** (± depth) around the curve.
- **Stage 8:** unified **Filter** labels (Cutoff / Reso / Env amt / Drive), LP/BP/HP names, **Cmd 38xx** hint and **A** (open lanes) on the instrument Filter block.

### Automation UX stage 2 (design A)

- Right-click › **Show automation** (or Add) opens the track lane without leaving the Instrument editor.
- Timeline "+ lane" strip: **last** toggles follow-last-touched; **show** opens the last knob's lane.

### Automation UX stage 1 (design A)
- Timeline lane headers show **Device > Parameter** (generated from the target).
- Lane colour follows the **parameter family** (cutoff cyan, resonance magenta, volume green, pan amber, FX mix violet, plugins teal).
- A **value scale** with units sits on the left of each timeline lane (log Hz for cutoff).
- Bigger points; **double-click** adds a point (plain click no longer drops one); hit radius 10 px.
- "+ Lane" menu has a **search** box.
- **Add automation lane** from a knob in timeline mode creates a **track** lane, keeps the Instrument editor open, and does not duplicate an existing lane.

- **The Browser:** a long panel on the right (**Ctrl+B** or the toolbar's **Browser** button; resizable, remembered) that lists everything ChipWave can load and is now the main way to load things. Guide: [BROWSER.md](BROWSER.md).
  - **8 category tabs:** Instruments (blank synths, every generator preset, your `.cwi` library, this song's instruments), Plugins (CLAP and VST3 instruments and effects from the scan), Samples (WAV / FLAC / MP3 / Ogg), Songs (demos, `.cwt` / `.cwt.toml`; MOD/MED listed, import planned), Presets, Grid (starter patches and Grid FX), Wavetables (built-in and imported WAV tables) and MIDI (listed, import planned).
  - **Search, tag chips** (Bass, Lead, Pad, Drums, Chip, FM…), **Category / Creator / Location columns** with counts, sort by name, type or rating, **colour-coded format badges** with a legend, **favourites** (heart) and **1–5 star ratings**, saved in the settings.
  - **Locations:** library, this song, favourites and **folders you add**, scanned in the background (never stalls the UI) and cached in `browser-index.json`.
  - **Load** with double-click or Enter (a new slot, the current instrument's sound for presets, its FX chain for effects, an audio clip for samples on the Timeline, songs with the usual save prompt), or **drag** onto a timeline track, an instrument slot, the FX view or the pattern editor, with a ghost and a drop hint. Files decode on a worker thread; every load is one undo step.
  - **Preview** on C-3 through the current track's mixer channel (auto-play toggle, Space, Esc).
- **Timeline tracks from the Browser and the headers:** guide: [TIMELINE.md › Tracks](TIMELINE.md#tracks-add-reorder-instruments).
  - **Drop an instrument, preset, `.cwi` or VST3 / CLAP plugin on a track header:** the track plays it (every note on the track switches; undo). **Drop below the last track:** a new track named after it, playing it. The target header lights up, or an insertion line shows "New track: <name>".
  - **Drag track headers up and down to reorder**, in timeline and tracker mode: the channel's block columns, mixer strip, name, clips and channel automation move with it, so playback is the same (tested).
  - **+ Add track** under the last header, and right-click › **Add track above / below / with instrument…** (opens the Browser's Instruments tab). Up to 32 tracks, with a clear message when full.
- **Find plugins (first-run plugin step):** scan the standard VST3 / CLAP folders automatically (optionally the whole drive), pick folders yourself, or skip. Runs in the background with progress, shows what it found and adds the folders to the plugin folders and the Browser's locations. Existing users see it once; it is always in **Settings › Plugins › Find plugins…** and the Browser's Plugins tab. Guide: [BROWSER.md › Find plugins](BROWSER.md#find-plugins), [PLUGINS.md](PLUGINS.md#finding-plugins).
- Old songs open and render as before; the Browser only reads until you load something.
- Limits: no MIDI or MOD/MED import yet, plugins aren't previewed, plugin preset files aren't listed, no custom tags, file favourites are keyed by path.

Guide: [TIMELINE.md › Finding your way around](TIMELINE.md#finding-your-way-around).
- **The Grid, modular patching:** **New… › Generator (grid)** and an **Add effect › Grid FX** device. Guide: [GRID.md](GRID.md).
  - **A node canvas in the lower panel** (the Grid tab): add modules (+ Module or right-click), drag them by the title, **drag cables from outputs to inputs**, click an input to unplug. Every edit is undoable.
  - **20 modules:** Note (pitch / gate / velocity), Macro, Audio In, Out, Osc (5 band-limited shapes, PM, PW), Wavetable (the Wave generator's 10 tables, mipmapped), Noise, Filter (SVF LP/BP/HP/notch), Ladder, ADSR, LFO (5 shapes), Mix, VCA, Math (7 modes), Logic (6 modes), Slew, Sample & Hold, Shaper (soft / fold / hard), Delay (with feedback and damping) and Knob. Feedback loops are allowed (one-sample delay).
  - **Polyphonic per voice**, compiled to a fixed processing order in fixed-size arrays inside each voice: nothing is allocated on the audio thread (tested with a lane and an LFO route on a module knob, and on Grid FX).
  - **Every module knob is automatable and a drag-to-modulate target** (`instrument.N.gen.K`; knobs 1–8 are the Grid macros and 43xy). Knob numbers stay with their module, so lanes survive patch edits.
  - **Grid FX:** the chain's audio comes in through Audio In; its Macro 1–8 and Mix are automatable / modulatable; **Edit patch...** in the FX view opens the canvas; starter patches Auto-Filter, Ring Mod and Comb Resonator.
  - **6 starter patches:** Grid Saw Bass, Grid Wavetable Pad, Grid FM Bell, Grid Karplus Pluck, Grid S&H Lead, Grid Chip Gate. Patches are saved with the song.
  - Old songs render bit-identically (all demos checked against the previous build). `--self-test` renders every starter patch and round-trips Grid instruments and FX through `.cwt`.
  - Inspired by Bitwig Studio's The Grid (idea only, no code or assets; credited). Our own canvas, no new dependency.
  - Limits: 32 modules / 128 cables per patch, 2 delays (≈85 ms) and 4 ladders per voice; mode menus aren't automatable; Grid FX exposes only its macros and Mix; no containers, sample player, sequencer or envelope follower modules, canvas zoom or separate patch files yet; older versions can't open Grid songs.

- **Wave, a wavetable synth generator:** **New… › Generator (wavetable)**. Guide: [GENERATORS.md › Wave](GENERATORS.md#wave-wavetable-unreleased).
  - **Two wavetable oscillators** with **position scanning** (smooth crossfades between frames), Semi/Fine and level each; **unison** up to 8 voices per oscillator with **Detune** and stereo **Spread**; a **sub** sine and **noise**.
  - **Band-limited:** every frame is stored as 10 FFT mipmaps (512 → 1 harmonics) and each note plays the richest one below Nyquist, so high notes don't alias (tested at 3.1 kHz: alias images below −74 dBFS).
  - ChipWave's **ladder filter** (LP/BP/HP, 12/24 dB, clean or vintage) with key tracking, drive and its own envelope, which can also sweep the table positions (**Env>Pos**); an amp envelope, glide and legato. 38xx–3Bxx move its cutoff and resonance.
  - **All 28 knobs are automatable** (`instrument.N.gen.K`), the first 8 are 43xy macros, and every one is a drag-to-modulate target. Dice, Mutate, locks, history and Bake work as on the other generators.
  - **10 built-in tables, generated in code** (Basic Shapes, Pulse Width, Harmonic Sweep, Formant Vowels from the Voice engine, FM Sweep, Sync Sweep, Wavefold, Bit Crush, Odd Harmonics, Digital Noise), so all are ours to ship. No third-party tables are included.
  - **Import WAV…:** single-cycle WAVs (any length up to 8 192 samples) and Serum-style wavetables (2 048-sample frames, `clm` chunk frame sizes read, up to 256 frames). The table is saved inside the song.
  - 6 presets: Wave Supersaw, Wave Vowel Bass, Wave Glass Keys, Wave Evolving Pad, Wave Chip Pluck, Wave Growl (also in the library and as `patch = "gen:…"` in text songs).
  - Old songs render bit-identically (all demos checked against the previous build) and the audio thread stays allocation-free (tested with 8+8 unison voices, a lane and an LFO on the position). `--self-test` checks the tables, aliasing, import and a `.cwt` round trip.
  - Design inspired by Vital by Matt Tytel and Surge XT's wavetable oscillator (ideas only; credited in About › Credits and THIRD_PARTY_LICENSES).
  - Limits: no warp modes or spectral morphing yet, no table drawing or sample-to-table conversion, modulators are per instrument (not per voice), octave mipmaps (see the guide), older versions can't open songs that use Wave.

- **VST3 hosting:** VST3 instruments and effects next to CLAP. Guide: [PLUGINS.md › VST3](PLUGINS.md#vst3-unreleased).
  - **Same everything as CLAP:** the scan (crash-guarded child process, cache), the **Add plugin instrument** browser and the **Plugin effect ›** menus (marked VST3), the parameter list, 8 macros and 43xy, automation lanes, drag-to-modulate, plugin delay compensation, state saved in the song, missing-plugin placeholders, offline render and `--self-test`.
  - **Editor:** the plugin's own VST3 editor is embedded in a ChipWave window on Windows, resizable both ways. Linux and macOS use the parameter list for now.
  - **Portable songs:** plugins are saved by their VST3 class id in the SDK's text form, which is the same on every OS. Text songs take `patch = "vst3:<class id>"`. Songs without VST3 plugins open and render exactly as before.
  - The audio thread stays allocation-free (preallocated event and parameter lists, tested). Parameters a plugin lists only as MIDI CC stand-ins (JUCE's 2,080) are hidden.
  - **Licence:** the VST 3 SDK is MIT since 3.8.0 (Steinberg Media Technologies GmbH); its notice is in the credits, `LICENSES/VST3_SDK_LICENSE.txt` and THIRD_PARTY_LICENSES. New dependency: the `vst3` crate (bindings by Micah Johnston, MIT/Apache-2.0). No plugins are bundled.
  - Tested with a new fixture (`plugins/cw-test-vst3`, which renders the same song as the CLAP fixture), Surge XT 1.3.4 VST3 (Linux, and the Windows build under Wine with its editor) and the VST 3 SDK samples (mda JX10/DX10/Piano/EPiano and effects, ADelay, AGain), built from source.
  - Limits: no VST3 editor on Linux/macOS, no program lists, no note expressions other than tuning, no MIDI CC mapping, sidechains or extra buses; macOS loading is untested.

- **Automation lanes on the timeline (Timeline M5):** guide: [TIMELINE.md › Automation lanes](TIMELINE.md#automation-lanes).
  - **Per-track lanes** under each track header, opened and closed with the **A** button. **+ lane** offers every automatable parameter: mixer, instrument, generator knobs, FX including plugin FX, return buses, master and modulation depths. Song lanes can be pinned to a track and unpinned again.
  - **Drawing:** click, drag, Ctrl-drag pencil, Alt-drag to **bend segments into curves**, double-click to delete, right-click for shapes.
  - **Clip automation:** a clip can have its own lanes, which move, loop, trim and split with the clip.
  - **Innermost lane wins** (clip, then track, then song). Lanes play live and in export; leaving timeline mode bakes them into song lanes.
  - Saved with the song (reader version 4 when a song uses them). Older songs open and render exactly as before, and the audio thread stays allocation-free (tested).
- **Audio clips (Timeline M4):** WAV, FLAC, MP3 and Ogg Vorbis files on the timeline. Guide: [TIMELINE.md › Audio clips](TIMELINE.md#audio-clips).
  - **Drop files on a track** (or right-click › **Import audio file here…**); decoding runs in the background. Clips draw their waveform.
  - Move, copy, trim, **loop** (drag past the end), **split**, mute; **fades** by dragging the top-corner handles (equal power, linear or S-curve) and **clip gain** (right-click). Overlapping clips crossfade.
  - Files play at their own speed: the sample rate is converted while playing, so live playback and **export** at any rate sound the same. Sample-accurate starts, seeks into a clip, seamless splits.
  - **Saved with the song:** stored inside the `.cwt` (the original bytes) or referenced by path (files over 64 MB, or by choice). A missing file opens with a warning; its clips stay, silent, and **Locate audio file…** relinks them. Songs with audio clips need reader version 3.
  - The audio thread stays allocation-free and songs without audio clips render exactly as before (tested). New dependency: Symphonia 0.5 (MPL-2.0, listed with its licence in THIRD_PARTY_LICENSES).
  - Limits: no time-stretch / repitch, reverse, clip FX or streaming yet; files are held in memory (warning above 5 minutes, refused above 20).
  - Tests: decoding (WAV exact, FLAC/MP3/Ogg fixtures), engine (frame-exact start, own speed at three output rates, trim/loop/split/fades/gain, seek, crossfade, allocation, export tail), files (embedded, referenced, moved, missing), UI (drop, fade handles, menu, tracker-mode drop). `--self-test` plays and round-trips an audio clip.

- **Drag-to-modulate:** Bitwig-style modulators. Guide: [MODULATION.md](MODULATION.md).
  - **+ Modulator** (above the instrument editor's cards, and in the FX view) adds an LFO, envelope, random, velocity, keytrack, mod wheel, macro or the instrument's own LFO. Each is a chip with a live meter.
  - **Drag a chip onto any knob** (synth, Voice, generator, built-in FX, plugin FX parameters) to route it. The knob shows a coloured depth ring and a live dot; drag the ring's dot or **Alt-drag** the knob to set the depth. Right-click › **Modulate with ›** / **Remove**.
  - The Modulation tab has a **Modulators** card (shape, sync, rate, phase, retrigger, unipolar, ADSR, glide, smoothing, macro value) and a **Routings** card (depths in %, remove, **Lane** for an automatable depth `mod.K.amount`).
  - Synth-patch knobs without a target before (pulse width, detune, ADSR, glide, LFO depths, accent…) are now automatable and modulatable (`instrument.N.patch.<key>`).
  - Saved with the song (`modulation.toml`; older versions ignore it), undoable, follows instrument delete/move. Modulation adds on top of automation lanes; modulators restart with the song, so renders repeat exactly.
  - The audio thread stays allocation-free (tested) and songs without modulation render bit-identically (checked against the previous build with every demo). Plugin effect parameters now return to their own value when a lane or routing stops driving them.
  - Limits: modulators are per instrument, not per voice; plugin instrument macros, tempo and the mixer view's faders aren't drop targets; `.cwi` files don't carry modulators.
  - Tests: modulator engine, renders (LFO on a filter, envelope on sustain, FX and plugin parameters, depth lanes, zero depth = no change), allocation, files, instrument edits, and UI tests for drop, ring, Alt-drag, undo, Routings card and FX sliders. `--self-test` renders a modulated note.

- **Piano roll and note clips (Timeline M3a/M3b):** a new lower-panel tab, **Piano roll**. Guide: [TIMELINE.md › Piano roll and note clips](TIMELINE.md#piano-roll-and-note-clips).
  - **Blocks:** it edits the selected clip's block column (or the pattern editor's current column) as bars on the row grid. Draw, move, resize (moves the note-off), right-click to delete, velocity lane = volume column, effect badges and an inspector (instrument, velocity, effect), plus keys (Del, arrows, Ctrl+A). Only the touched cells change.
  - **Note clips:** polyphonic clips with free timing. Make one with **New note clip here** or Shift+double-click, and open it with a double-click or Enter. In the roll: snap grid, **Q** quantise, chord stamp in the song key, scale highlight, playhead. Timeline clips show note previews, and make unique copies the notes.
  - **Playback:** 8 voices per track with voice stealing, sample-accurate starts, loops, trims, chance (repeatable), seek re-strike, and plugin instruments.
  - **MIDI:** live recording into a note clip on the cursor track while the timeline plays (time stamped, latency compensated), and **Capture played MIDI here** for the phrase you just played.
  - Songs without note clips play exactly as before (tested). Limits: no tracker conversion of note clips, no MIDI file import, no CLAP note ids or expressions yet, and plugin notes are tick-quantised.
  - Tests: cell round trips; UI tests for drawing, dragging, the velocity lane, keys, chords, quantise, recording and Capture; engine tests for chords, stealing, sample timing, seeks, loops and chance, and bit-exact block timelines. `--self-test` plays a note-clip chord.
- **Plugin effects (CLAP FX):** any installed CLAP audio effect can go into an instrument's FX chain. Guide: [FX.md › Plugin effects](FX.md#plugin-effects-clap-unreleased).
  - Every add-effect menu (FX view **+ Device**, the FX tab's **+ Add effect**, right-click an instrument › **Add effect**) has a **Plugin effect ›** list from the plugin scan, with **Scan for plugins**.
  - The device panel shows the plugin's status and latency, **Editor…** (its own window), **Reload** and every parameter as a slider. Bypass, reorder, duplicate and remove work like built-in devices.
  - **Automation:** right-click a parameter › **Add automation lane**, or **+ Lane** › *instrument* › FX › parameter. Lanes also play in exports.
  - The plugin's state is saved with the song (and in `.cwi` / the library). A missing plugin is **bypassed with a notice**, keeps its saved state, and is listed when the song opens; **Reload** retries.
  - **Plugin delay compensation:** a plugin device adds 64 samples plus the latency it reports, and the other channels are delayed to match, live and in export. Bypass keeps the timing.
  - The audio thread stays allocation-free (tested). Songs without plugin effects play exactly as before; songs with them save `min_reader_version = 2`.
  - Limits: no plugin effects on the return buses or the master yet (they have no device chains), plugin instruments and live playing aren't compensated, no MIDI learn on plugin effect parameters, `.cwt.toml` can't describe plugin devices.
  - Tests: a fixture CLAP effect (`ChipWave Test FX`: gain, polarity flip, 32-sample latency) checks processing, automation, bypass timing, delay compensation, allocation-free rendering, missing plugins, state round trips and file compatibility, plus a UI test. `--self-test` checks a missing effect; `CHIPWAVE_SELFTEST_PLUGIN_FX=<file.clap>` runs a real one (checked with Surge XT Effects, not bundled).
- **Timeline mode (Timeline M2):** songs can now be arranged with clips. A song is in **tracker mode** (the order list plays, as before) or **timeline mode** (the clips are the song). Full guide in [TIMELINE.md](TIMELINE.md#timeline-mode).
  - **Switching:** **Switch to timeline mode** in the Timeline toolbar, or any clip edit in a tracker-mode song, asks first. The switch plays the same samples, and Undo puts it back (the switch and the edit are separate steps). **Back to tracker mode…** turns the clips into blocks and an order list. **New songs start in timeline mode** (Del's decision; off with Settings › New songs). Old songs open in tracker mode and play bit-exactly.
  - **Clip editing:** drag to move (across tracks, snapped; Shift = rows), **Alt-drag** to copy, drag the right edge to resize (past the block it **loops**) and the left edge to **trim**. **S** split, **Ctrl+D** duplicate (linked), **Ctrl+Shift+D** make unique, **Ctrl+J** glue, **M** mute, **Del** delete, Ctrl/Shift-click and box selection, Ctrl+A. Double-click empty space for a new block there. Right-click menus for clips, markers and tracks.
  - **Snap** menu (Auto / Bar / Beat / Row), a **loop region** (Shift-drag the ruler, Ctrl+L around the selection, **L** / **Loop** toggles it) and **markers** (+ Marker / Shift+M; click to jump, drag, double-click to rename, right-click to delete).
  - **Per-track speed** (right-click a track header): ticks per row for that track's effects; timing stays the same.
  - **The engine plays the clips directly** (a playback plan built off the audio thread), with exact seeks: tempo, instruments, volumes and other state are chased, and held sustaining notes re-struck. **Space** on the Timeline plays from its play marker.
  - **Saving:** timeline-mode songs add `timeline.toml` and need reader version 2; older versions refuse them with "please update". **File › Export tracker-compatible copy…** saves a tracker-mode copy that 0.2.4.0 and older can open. Export can render just the **loop region**.
  - Tests: a moved clip plays exactly a bar later; split, glue, make unique and the tracker copy render the same samples; loop wrap; seek chase; per-track speed; save/load; UI tests for the prompt and undo, drags, edges and keys. `--self-test` checks timeline-mode playback and `timeline.toml`.
- **Timeline view (Ctrl+T), read-only:** a DAW-style view of the song next to Pattern / Arranger / Mixer (VIEW tab **Timeline**, View › Timeline, `Ctrl+T`; `Ctrl+Tab` cycles Arranger → Timeline → Mixer). **Tracks are channels**, and each clip is one column of one block, placed where the order list plays it. Runs of the same block become one looped clip with notches, and the arranger's section roles show as markers. Milestones M0 and M1 of [DAW_TIMELINE_PLAN.md](DAW_TIMELINE_PLAN.md); full guide in [TIMELINE.md](TIMELINE.md).
  - Track headers with colour, number, name, instrument, **M / S**, a volume mini-fader (double-click = 0 dB) and the channel meter, all wired to the mixer.
  - Bar ruler (or minutes:seconds) with a `bar.beat · m:ss` readout. Clips show block names and note previews.
  - The playhead follows playback (Follow pages it a third of the way in). Click the ruler to seek, snapped to the bar like the arranger (Alt = exact row).
  - Ctrl+wheel zooms around the mouse. Wheel / Shift+wheel scroll, Alt+wheel sets track height, and there are + / − / **Fit** (F), a mini-map strip and a vertical scroll bar.
  - **Double-click a clip** to open that block in the pattern editor, at that column and the row you clicked. Enter opens the selected clip. F11 gives the timeline full height.
  - Drawn with a few meshes and only the visible clips. A test draws more than 9,000 clips within the frame budget.
  - Keys typed in the Timeline never enter notes.
- **New songs open on the Timeline** (Del's decision): File › New shows 8 empty tracks with "double-click to write" outlines. Turn it off under **Settings › New songs › Open on the Timeline view**. Existing songs open as before and play bit-exactly. Timeline *editing* and timeline-mode songs come in M2.
- **Timeline model (M0):**
  - 960 PPQ ticks; tracks, clips (block-column and note clips, offset, loop, mute, gain, fades, seed, clip automation); a tempo map with ramps, a time-signature map, markers (also per track) and a loop range.
  - MIDI 2.0–style notes with 16-bit velocity and release velocity (M2-115 scaling), per-note tuning, chance, and per-note expressions numbered like CLAP note expressions. Automation is stored as 0–1 values, and the innermost lane wins.
  - Each clip has a random seed: randomness depends only on the seed and the loop pass, so exports and seeking stay bit-exact. Note data is shared (`Arc`) so undo stays cheap.
  - Converters both ways (order list → timeline, and timeline → blocks + order list). Tests check the round trip renders **bit-exact** for every demo, the 0.2.3.5 / 0.2.3.6 fixture songs and a synthetic song with pattern breaks, and `--self-test` checks it too.
  - (M0/M1: nothing was saved from the timeline; since M2, only timeline-mode songs save it.)
- **Songs from newer versions are refused cleanly:** `min_reader_version` is now checked when loading `.cwt` and `.cwt.toml` files. v0.2.3.16 brings **plugin instruments**: ChipWave now hosts **CLAP** instrument plugins (Surge XT and others) as normal instruments. Details: [PLUGINS.md](PLUGINS.md).

- **Scanner:** checks the standard CLAP folders for Windows, macOS and Linux, plus `CLAP_PATH` and your own folders (Settings → Plugins). Each plugin is checked in a separate ChipWave process, so crashes, exceptions and hangs (20 s timeout) can't take the app down, and Windows crash dialogs are suppressed. Results are cached and only changed files are re-checked. `chipwave --scan-plugins` prints the results. VST3 files are listed as "not hosted yet".
- **New → Plugin instrument…:** a searchable browser that scans the first time it opens.
- **Playing:** one instance per channel, created off the audio thread. The audio thread never allocates (a test checks this). Notes and velocity are sent as CLAP note events, and glide / slides as per-note tuning. Instances follow the device sample rate and block size, and play in stereo through the instrument FX chain, the mixer and the limiter. Panic reaches every instance.
- **Plugin panel:** status, **Configure…** (the plugin's own editor: embedded on Windows, floating-only elsewhere for now) and **Reload**. Eight **macros** map to any parameter. The full **parameter list** has search and live sliders, and right-click puts a parameter on a macro.
- **Macros everywhere:** `43xy` sets macro *x* from the pattern, the automation lanes offer "Macro 1–8" for plugin instruments, and MIDI learn can drive the macros.
- **State:** the plugin's preset is saved base64-encoded in `.cwt`, `.cwi` and the instrument library. It's captured before every save, autosave and export, without adding an undo step. Text songs take `patch = "clap:<id>"` with `plugin_path`, `state` and `macros`.
- **Missing plugins:** the instrument becomes a silent placeholder that keeps its data, and a warning appears when the song opens.
- **Offline render:** WAV/MP3 export and `--render` create their own instances with the saved state.
- **macOS:** `.clap` bundles load `Contents/MacOS/<binary>`.
- **Self-test:** checks the missing-plugin placeholder and the cached plugin list. `CHIPWAVE_SELFTEST_PLUGIN=<file>` also renders a note through a real plugin.
- **Tests:** ChipWave's own tiny CLAP fixture (`plugins/cw-test-synth`, also built as crash and hang copies) covers the scanner, crash/hang guard, playback, state round-trip, render, allocation-free processing, missing plugins, `43xy` and instrument renumbering. v0.2.3.11 adds a **Transform** section to the Voice instrument: three blendable stages after the formants, each with its own amount, and a master **Blend** (dry ↔ transformed; 0 = off, the default, so older songs render bit for bit as before). **Metallic resonance**: six modal resonators (constant-peak-gain two-pole form after Smith & Angell 1982) tuned to the note (± 24 st) or a fixed pitch, with harmonic, metal (TR-808), bell, bar or odd ratios, decay (ring time), damping and stereo spread; the poles always stay inside the unit circle and the output is soft-limited. **Digital distortion**: pre high-pass, drive into hard clip or an in-phase wavefold, bit depth, sample-rate reduction (raw aliasing or filtered), a ring modulator at the note × ratio and a post low-pass; every step keeps polarity, so blending never cancels. **Sub bass**: a sine one or two octaves under the note and/or an octave divider, following the voice's amplitude, saturated for growl, behind a Linkwitz-Riley crossover; below the crossover the sub is clean and the whole voice is mono (side-only high-pass, the side is ≥ 40 dB down below 120 Hz in the tests); the sub joins after the patch filter. **Formant drop** (0–12 st) lowers the formants for a monster voice. **Order**: Dist > Res or Res > Dist. Five presets: **Metal Demon**, **Digital Ghost**, **Sub Beast**, **Cyber Choir**, **Ritual Growl**. New pattern effects **`3Fxx`** blend, **`40xx`** resonance, **`41xx`** digital, **`42xx`** sub (00 = instrument, 01–FF = 0–100 %). The stages are also FX devices for any instrument (**Metal resonator**, **Digital distortion**, **Sub bass**; the resonator and the sub sine follow the channel's note; `40`–`42` set their mix), with 8 device presets. Text songs merge `[instrument.voice.transform]` tables key by key. `--self-test` renders the presets and devices through the limiter; `--screenshot --view transform`. Credits (Smith & Angell, Fletcher & Rossing, Linkwitz, TR-808, analog octave pedals) are in Help > About, the README and THIRD_PARTY_LICENSES.txt. Details: [VOICE.md](VOICE.md#transform-02311).

v0.2.3.10 (roadmap batch 4) teaches the Voice instrument to **speak** and adds **chop / slice** to the sample editor. **Words:** a Voice has a list of up to 16 short words (`ka`, `ta`, `sha`, `dum`, …; typed in the new Words row) and each new note speaks the next one; **`3Exx`** speaks word `xx` (on a held note it says it again). Words are phoneme strings, not text-to-speech: plosives (p b t d k g) are a silent closure, a 10 ms noise burst at the place of articulation and aspiration; fricatives (s z sh f v h) are band-passed noise (z and v voiced); nasals (m n ng) are a murmur that opens into the vowel; vowels glide in from consonant **formant loci** (Delattre, Liberman & Cooper 1955; fricative and burst spectra after Stevens, *Acoustic Phonetics*). A **Speech rate** slider scales the timing (0.25–3×). **Throat mode** (Tract: Formant / Throat): instead of five formant filters, the glottal pulse drives a simulated **vocal tract**, a 44-segment Kelly–Lochbaum waveguide with a nasal branch and a tongue/lips/velum model inspired by **Pink Trombone by Neil Thapen** (MIT; reimplemented in Rust, no code copied); the vowel chips set the tongue shape, consonants close the tract at the lips, tongue blade or tip and open the velum for nasals. New presets: **Talk Ka-Ta**, **Throat Ahh**, **Throat Speech**, **Demon Words**. Throat voices cost more CPU (8 render about 6× realtime on one core). **Sample slicing** (Sample editor, new Slice row): **Transients** finds the hits (sensitivity and shortest-gap controls; slice points snap to zero crossings), **Grid** cuts into 2–64 equal parts; slices are numbered on the waveform, click one (or Prev / Next) to select it so Normalise, Reverse, Fade in/out and Gain work on that slice; Alt+click adds a slice, right-click a marker removes it. **To instruments** turns every slice into its own sample instrument (with 1 ms / 3 ms declick fades); **To notes** also writes them into the current block on the cursor channel at the rows where they fall at the song tempo, so the loop plays back and can be rearranged. One undo step. `--self-test` adds a words / throat / slicing check; `--screenshot` adds `--view speech|slice`. Credits for Pink Trombone (Neil Thapen, MIT notice included), Kelly & Lochbaum, Delattre et al. and Stevens are in Help > About, the README and THIRD_PARTY_LICENSES.txt. Songs from 0.2.3.9 and older load unchanged (Voices without words behave as before). Details: [VOICE.md](VOICE.md), [SAMPLES.md](SAMPLES.md).
