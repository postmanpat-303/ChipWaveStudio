# ChipWave Studio changelog

Newest first. Older screenshots mentioned below live in `dist/`.

## 0.2.4.0: ChipWave Tracker is now ChipWave Studio

- **New name:** ChipWave Tracker is now **ChipWave Studio**, to tell it apart from an unrelated paid iOS chiptune app called "ChipWave" that appeared on the App Store in August 2026. Same app, same file formats, same settings folder (`%APPDATA%\ChipWave`, `~/Library/Application Support/ChipWave`, `~/.config/chipwave`), so settings, recent files, keys and the instrument library carry over untouched. Plan and details: [RENAME.md](RENAME.md).
  - **GitHub:** the repo is now [postmanpat-303/ChipWaveStudio](https://github.com/postmanpat-303/ChipWaveStudio); old ChipWaveTracker links (repo, releases, downloads, API) redirect. The website moved to [postmanpat-303.github.io/ChipWaveStudio](https://postmanpat-303.github.io/ChipWaveStudio/).
  - **App:** window title, About screen, eframe app id, MP3 "encoded by" tag, the `app` line in saved songs and instruments, the CLAP host name and the update check's User-Agent (`ChipWave-Studio/<ver>`) say ChipWave Studio. The update check asks the new repo and falls back to the old address if that answers 404; older versions asking the old address are redirected by GitHub, and the download file names (`ChipWave-<ver>-setup-x64.exe`, `ChipWave-setup-x64.exe`, `ChipWave-macos-universal.dmg`, …) are unchanged so their updaters and Wave Hub still find them.
  - **Windows installer:** "ChipWave Studio" in the Start menu, desktop shortcut and Add/Remove Programs. The install folder (`Program Files\ChipWave Tracker`), `ChipWave.exe` and the uninstall/registry keys keep their old names, so installing over ChipWave Tracker (also silently with `/S`) updates the same install with one Add/Remove entry, and tools that look for it (Wave Hub) still find it. The old "ChipWave Tracker" Start-menu folder and desktop shortcut are removed. The installer now reads its install-folder key from the 64-bit registry view.
  - **macOS:** the menu bar, Dock and disk image say ChipWave Studio; the bundle stays `ChipWave.app` with the same bundle id (`com.postmanpat303.chipwave`), so it replaces the old app and keeps its permissions.
  - **Linux:** a `.desktop` file, AppStream metainfo and the MIME types for `.cwt`/`.cwpatch` in `packaging/linux/`.
  - Icon files renamed to `assets/icon/chipwave_studio*` (same pictures). Version 0.2.4.0 (Cargo `0.2.4+fix.0`); a test checks every 0.2.3.x install sees it as newer.
- **Transpose buttons:** transposing no longer needs the keyboard. The Block bar has **Transpose -12 / -1 / +1 / +12**, and **Edit › Transpose** has Up / Down semitone, Up / Down octave (with their shortcuts shown) and **Transpose by…** for any amount from -24 to +24. They do exactly what `Alt+=` / `Alt+-` (Shift = octave) do: the selection, or the cursor channel when nothing is selected; one undo step per press, and the status bar message. Tooltips say what will move ("selection (rows 04–07, channel 2)" or "channel 3 (whole block 06)") and the shortcut. The Block bar stays on one line in windows about 1600 px wide or more; narrower windows wrap the right-hand group (and then Transpose) onto the next line without overlapping. UI tests cover the buttons, undo, the menu, Transpose by… and the layout at four widths. The screenshot harness takes `CHIPWAVE_SHOT_SEL=r0,c0,r1,c1` for a selection and `CHIPWAVE_SHOT_NOPLAY=1` to stay stopped.
- **Windows icon:** ChipWave.exe and the setup exe showed the generic program icon in Explorer and Edge's download list on some PCs. The embedded `assets/icon/chipwave_studio.ico` stored every size (16 to 256 px) as PNG, and Windows often can't draw small PNG frames. It is now a standard ICO: 256 px as PNG, and 128, 64, 48, 32, 24 and 16 px as 32-bit BMP with alpha (fixed icon made by the imagine assistant). Both the app exe resource and the NSIS installer/uninstaller icon use it. The committed `.ico` is the source of truth (nothing regenerates it); `scripts/check-ico.py` checks the file before the build and the icons embedded in `ChipWave.exe` and the setup exe after, and `scripts/package-windows.sh` fails if a small frame is PNG. The window/taskbar icon at runtime still comes from the 256 px PNG.

v0.2.3.17 counts **pattern rows in decimal** and makes **block length** easy to change.

  - The pattern gutter now counts 00–63 for a 64-row block instead of hex 00–3F, with three digits for blocks over 100 rows.
  - The beat and bar highlights are kept.
  - **View → Row numbers → Decimal / Hex** and **Settings → Look → Row numbers** switch between them; the choice is saved.
  - The new **Row 32/64** readout in the status bar, the play-marker message and MIDI-recording messages use the same numbering.
  - Effect, instrument, volume and order numbers stay hex. The docs note that `1Dxx` takes a hex row (`1D20` = row 32).

  - Before this version the app had no way to change a block's length: only Fill to length (derived blocks) and the text-song `lines`.

  - Every change is one undo step.
  - The arranger, ruler, play marker, song length and export follow at once, and a resized derived block becomes ordinary.
  - The length is stored per block in `.cwt` (`lines` in text songs), so the file format is unchanged.

v0.2.3.16 brings **plugin instruments**: ChipWave now hosts **CLAP** instrument plugins (Surge XT and others) as normal instruments. Details: [PLUGINS.md](PLUGINS.md).

- **Scanner:** checks the standard CLAP folders for Windows, macOS and Linux, plus `CLAP_PATH` and your own folders (Settings → Plugins). Each plugin is checked in a separate ChipWave process, so crashes, exceptions and hangs (20 s timeout) can't take the app down, and Windows crash dialogs are suppressed. Results are cached and only changed files are re-checked. `chipwave --scan-plugins` prints the results. VST3 files are listed as "not hosted yet".
- **New → Plugin instrument…:** a searchable browser that scans the first time it opens.
- **Playing:** one instance per channel, created off the audio thread. The audio thread never allocates (a test checks this). Notes and velocity are sent as CLAP note events, and glide / slides as per-note tuning. Instances follow the device sample rate and block size, and play in stereo through the instrument FX chain, the mixer and the limiter. Panic reaches every instance.
- **Plugin panel:** status, **Configure…** (the plugin's own editor: embedded on Windows, floating-only elsewhere for now) and **Reload**. Eight **macros** map to any parameter. The full **parameter list** has search and live sliders, and right-click puts a parameter on a macro.
- **Macros everywhere:** `43xy` sets macro *x* from the pattern, the automation lanes offer "Macro 1–8" for plugin instruments, and MIDI learn can drive the macros.
- **State:** the plugin's preset is saved base64-encoded in `.cwt`, `.cwi` and the instrument library. It's captured before every save, autosave and export, without adding an undo step. Text songs take `patch = "clap:<id>"` with `plugin_path`, `state` and `macros`.
- **Missing plugins:** the instrument becomes a silent placeholder that keeps its data, and a warning appears when the song opens.
- **Offline render:** WAV/MP3 export and `--render` create their own instances with the saved state.
- **macOS:** `.clap` bundles load `Contents/MacOS/<binary>`.
- **Self-test:** checks the missing-plugin placeholder and the cached plugin list. `CHIPWAVE_SELFTEST_PLUGIN=<file>` also renders a note through a real plugin.
- **Tests:** ChipWave's own tiny CLAP fixture (`plugins/cw-test-synth`, also built as crash and hang copies) covers the scanner, crash/hang guard, playback, state round-trip, render, allocation-free processing, missing plugins, `43xy` and instrument renumbering. Surge XT 1.3.4 (CLAP) was tested on Linux and in the Windows build under Wine (self-test PASS).
- **Not yet:** VST3 hosting (COM host, parameter panel, IPlugView editors), plugin effects in the FX chain, embedded editors on macOS and Linux, undo for plugin state. Dexed has no CLAP build, so it waits for VST3. Vital wasn't tested.
- **Credits:** CLAP (free-audio, MIT), clap-sys, clack (design reference), Carla and Ardour (scanning ideas, no code copied), libloading, windows-sys, Surge XT (testing). They're listed in About, the README and THIRD_PARTY_LICENSES.
- Also: CI's real-time speed test for the Throat voice is now robust on slow CI machines. Old songs play bit-identically.

v0.2.3.16 adds a **Panic** button: a small **Panic** at the far right of the top toolbar (and **Ctrl+.**, rebindable in Settings > Keys) stops all sound at once, also while stopped. Playback stops, every voice and held MIDI note is cut after a 3 ms fade (no click), the sustain pedal and pitch bend are cleared, delay / reverb tails and every insert-FX and return state are wiped, the master limiter is reset and every hosted plugin gets all-notes-off / all-sound-off (CC 120 + 123 or a CLAP note choke) plus a plugin reset. The UI only sets an atomic flag; the audio thread does the work without allocating. ChipWave has no MIDI output, so nothing is sent to external gear. Tests: silence within 5 ms of a panic with long delay + reverb tails, while stopped, allocation-free, plugin voices, and a UI test for the button's place and the shortcut.

v0.2.3.11 adds a **Transform** section to the Voice instrument: three blendable stages after the formants, each with its own amount, and a master **Blend** (dry ↔ transformed; 0 = off, the default, so older songs render bit for bit as before). **Metallic resonance**: six modal resonators (constant-peak-gain two-pole form after Smith & Angell 1982) tuned to the note (± 24 st) or a fixed pitch, with harmonic, metal (TR-808), bell, bar or odd ratios, decay (ring time), damping and stereo spread; the poles always stay inside the unit circle and the output is soft-limited. **Digital distortion**: pre high-pass, drive into hard clip or an in-phase wavefold, bit depth, sample-rate reduction (raw aliasing or filtered), a ring modulator at the note × ratio and a post low-pass; every step keeps polarity, so blending never cancels. **Sub bass**: a sine one or two octaves under the note and/or an octave divider, following the voice's amplitude, saturated for growl, behind a Linkwitz-Riley crossover; below the crossover the sub is clean and the whole voice is mono (side-only high-pass, the side is ≥ 40 dB down below 120 Hz in the tests); the sub joins after the patch filter. **Formant drop** (0–12 st) lowers the formants for a monster voice. **Order**: Dist > Res or Res > Dist. Five presets: **Metal Demon**, **Digital Ghost**, **Sub Beast**, **Cyber Choir**, **Ritual Growl**. New pattern effects **`3Fxx`** blend, **`40xx`** resonance, **`41xx`** digital, **`42xx`** sub (00 = instrument, 01–FF = 0–100 %). The stages are also FX devices for any instrument (**Metal resonator**, **Digital distortion**, **Sub bass**; the resonator and the sub sine follow the channel's note; `40`–`42` set their mix), with 8 device presets. Text songs merge `[instrument.voice.transform]` tables key by key. `--self-test` renders the presets and devices through the limiter; `--screenshot --view transform`. Credits (Smith & Angell, Fletcher & Rossing, Linkwitz, TR-808, analog octave pedals) are in Help > About, the README and THIRD_PARTY_LICENSES.txt. Details: [VOICE.md](VOICE.md#transform-02311).

v0.2.3.10 (roadmap batch 4) teaches the Voice instrument to **speak** and adds **chop / slice** to the sample editor. **Words:** a Voice has a list of up to 16 short words (`ka`, `ta`, `sha`, `dum`, …; typed in the new Words row) and each new note speaks the next one; **`3Exx`** speaks word `xx` (on a held note it says it again). Words are phoneme strings, not text-to-speech: plosives (p b t d k g) are a silent closure, a 10 ms noise burst at the place of articulation and aspiration; fricatives (s z sh f v h) are band-passed noise (z and v voiced); nasals (m n ng) are a murmur that opens into the vowel; vowels glide in from consonant **formant loci** (Delattre, Liberman & Cooper 1955; fricative and burst spectra after Stevens, *Acoustic Phonetics*). A **Speech rate** slider scales the timing (0.25–3×). **Throat mode** (Tract: Formant / Throat): instead of five formant filters, the glottal pulse drives a simulated **vocal tract**, a 44-segment Kelly–Lochbaum waveguide with a nasal branch and a tongue/lips/velum model inspired by **Pink Trombone by Neil Thapen** (MIT; reimplemented in Rust, no code copied); the vowel chips set the tongue shape, consonants close the tract at the lips, tongue blade or tip and open the velum for nasals. New presets: **Talk Ka-Ta**, **Throat Ahh**, **Throat Speech**, **Demon Words**. Throat voices cost more CPU (8 render about 6× realtime on one core). **Sample slicing** (Sample editor, new Slice row): **Transients** finds the hits (sensitivity and shortest-gap controls; slice points snap to zero crossings), **Grid** cuts into 2–64 equal parts; slices are numbered on the waveform, click one (or Prev / Next) to select it so Normalise, Reverse, Fade in/out and Gain work on that slice; Alt+click adds a slice, right-click a marker removes it. **To instruments** turns every slice into its own sample instrument (with 1 ms / 3 ms declick fades); **To notes** also writes them into the current block on the cursor channel at the rows where they fall at the song tempo, so the loop plays back and can be rearranged. One undo step. `--self-test` adds a words / throat / slicing check; `--screenshot` adds `--view speech|slice`. Credits for Pink Trombone (Neil Thapen, MIT notice included), Kelly & Lochbaum, Delattre et al. and Stevens are in Help > About, the README and THIRD_PARTY_LICENSES.txt. Songs from 0.2.3.9 and older load unchanged (Voices without words behave as before). Details: [VOICE.md](VOICE.md), [SAMPLES.md](SAMPLES.md).

v0.2.3.9 (roadmap batch 3) adds **instrument management** and a **chord helper**. Instruments: double-click to rename, **Up / Down** and right-click **Move up / down** reorder slots with every note, lane and render cache following (the song renders identically), a search box over long lists, and right-click **Use this instead of** swaps which instrument the notes in the song (or only this block) play. A new **instrument library** (File > Instrument library…, or Library… under the list) shows the song's instruments, your library folder (`.cwi` files; sub-folders are categories; Settings > Files & Safety sets the folder) and the factory sounds side by side with search, kind filters, `›` audition, `+` add and right-click **Replace sound of XX (keep its notes)**. Instruments save and load as **`.cwi`** files (a ZIP with `instrument.toml` and, for samples, `sample.wav`): right-click > Save to library / Export .cwi…, File > Import / Export instrument, or drop a `.cwi` on the window. **Chord helper** (Song > Chord helper…, or Chords… in the block bar): a song key (13 scales) that you pick or **detect** with the Krumhansl–Schmuckler algorithm (Krumhansl & Kessler 1982 profiles); chord pads per scale degree (triad, 7th, sus2, sus4, add9, power; octave and inversion) that preview with the current instrument; a progression built from pads or 10 presets; **Write into block** as chords (one tone per channel), an arpeggio (up/down/up-down/random, rate, octaves) or a bass line (whole, 8ths, offbeat, rolling 16ths, octaves), one undo step. **Scale lock** snaps typed and MIDI notes to the key (shown as *lock A minor* in the block bar). The key is saved in `.cwt` files and as `key = "A minor"` in text songs. `--self-test` also checks `.cwi` round trips, key detection and chord writing; `--screenshot` adds `--view library|chords`. Credits for Krumhansl & Kessler and Scaler (inspiration only) are in Help > About, the README and THIRD_PARTY_LICENSES.txt. Songs from 0.2.3.8 and older load unchanged. Details: [INSTRUMENT_LIBRARY.md](INSTRUMENT_LIBRARY.md), [CHORDS.md](CHORDS.md).

v0.2.3.8 (roadmap batch 2) raises the channel limit from **8 to 32**, set per song (the **Channels** box in the block bar or the Song menu, 1–32; a text song's `tracks = N`). The pattern editor gets a channel scroll bar under the grid ("channels 9–16 of 32", click or drag; the cursor channel always stays in view, Tab walks all channels). The mixer's channel strips scroll beside the pinned master and limiter panel with their own bar ("channels 1–7 of 32 · drag / Shift+wheel"). The automation **+ Lane** menu groups channel targets per channel (and per 8 channels above 8). Undo keeps one step per channel for all 32 (mute/solo toggles never merge). Engine: a muted or quiet channel takes its mixer gain at once when playback starts instead of ramping from 0 dB over 5 ms. CPU: 32 busy channels of the demo render about 4.5× faster than realtime on one core (test `thirty_two_busy_channels_render_fast_and_allocation_free`), and an idle channel costs almost nothing. `--screenshot` accepts `--song file` (.cwt or .cwt.toml). Songs from 0.2.3.6/0.2.3.7 load unchanged; a song with more than 8 channels opened in 0.2.3.7 or older keeps only its first 8. Details: [PATTERN_EDITOR.md](PATTERN_EDITOR.md), [MIXER.md](MIXER.md).

v0.2.3.7 is the first batch of the improvement roadmap. **Master limiter and loudness meter:** a lookahead true-peak brickwall limiter on the master and in every export (default ceiling −1.0 dBTP; gain, ceiling, release, bypass = the old soft clipper), with a **Limiter & loudness** panel pinned to the right of the mixer: gain reduction, momentary / short-term / integrated LUFS and true peak per ITU-R BS.1770-4 / EBU R 128, plus a loudness-target hint (streaming −14, podcast −16, club −9, broadcast −23). Exports go through the same limiter (bit-identical to realtime), *Normalise* now works by true peak, and the export status reports LUFS and dBTP. **Per-row filter commands:** `38xx` cutoff, `39xx` resonance, `3Axx`/`3Bxx` cutoff slide up/down per tick. **303 glide and accent:** per-instrument Glide time + Legato (held notes glide without retrigger), `3Cxx` glide on/off per note, Accent amount + velocity threshold, `3Dxx` accent per note (louder, more open filter, shorter decay); `01`/`02` are unchanged. **Effect fixes:** the Reverb device has a Low cut (default 200 Hz) and High cut (default 16 kHz) on its wet signal (return B shows both); the **fold** distortion no longer inverts polarity, so a dry/wet blend thickens instead of cancelling (100 % wet folds sound the same as before). Engine: automation is evaluated on a fixed 32-frame grid instead of per audio callback, so output no longer depends on the buffer size. Credits for BS.1770, EBU R 128, libebur128, pyloudnorm and the Signalsmith limiter design are in Help > About, the README and THIRD_PARTY_LICENSES.txt. Details: [MIXER.md](MIXER.md), [PATTERN_EDITOR.md](PATTERN_EDITOR.md).

v0.2.3.6 adds the **Voice (glitch) instrument**: synthetic "ahh, eee, ohh, err" vowel chops for dark psytrance, with no samples. A glottal pulse (breath, jitter, tension) drives five parallel formant filters, and the vowel morphs through a sequence built from vowel chips (A E I O U ER AE). There are tempo-synced steps, random babble, Bass/Tenor/Alto/Soprano/Demon registers, formant shift, LFO > vowel / shift, a chop gate and a stutter (beat-repeat) on every note. It is reached from **New… > Voice (glitch)** or right-click an instrument > **New instrument**, with 6 presets: Demon Ahh, Choir Eee, Glitch Babble, Robot Err, Stutter Ohh and Whisper Ooh. The new pattern effects **30–37** set the vowel, sequence step, formant shift, stutter (`33xy`, on any instrument), stutter pitch, breath, babble and chop per row. See [VOICE.md](VOICE.md). The design is inspired by Mutable Instruments Plaits by Emilie Gillet (MIT), with formant data from the Csound manual and Peterson & Barney (1952); the credits are in Help > About, the README and THIRD_PARTY_LICENSES.txt. **File > Demo songs** lists the built-in demos (Lumen Drift and Hollow Ritual; Help > Load demo song still loads Lumen Drift). The toolbar fix: the MIDI / Chord / Rec indicators move to their own row instead of overlapping the view tabs on narrower windows (about 1600 px with the latency text shown). Songs from 0.2.3.5 load unchanged (test fixture `tests/fixtures/chipwave-0.2.3.5-song.cwt`).
